# Narrative Compaction: Theory and Implementation

## The Problem

LLM coding agents degrade over long sessions — not because the model gets dumber, but because its attention is diluted across an ever-growing context window filled with stale file reads, superseded diffs, and resolved intermediate reasoning. When Claude Code's automatic compaction fires at the context limit, it performs generic lossy summarization that discards structured state indiscriminately.

Prism's session forensics quantify this precisely. In a representative 4.5-hour session (81 prompts, 658 tool calls, 204.8M tokens):

- 97.6% of tokens went to "subagents" — but 2 of the 9 were actually compacted continuations of the main session, not spawned agents
- The main session compacted twice, each time paying ~4M tokens in cache-creation to rebuild the context
- The compaction happened reactively at 100% context — far too late for the narrative to survive intact

The prevailing assumption is that more context equals better performance. The evidence says the opposite: **a precise narrative frame in a clean context window outperforms a full context window where the narrative is buried under 200K tokens of stale material.**

## Theoretical Foundation

### The Winstonian Bet

This system implements a specific claim from Patrick Winston's story understanding model of intelligence: that cognition operates through narrative frames, not raw information accumulation. The model isn't processing tokens — it's "understanding a story" about what it's doing. If you can extract and re-inject the right story frame, the model performs better than it would with a full but noisy context window.

The key insight is that the compact focus string is not a *summary* — it is a *lens*. It tells the compact (or the clear-and-rebuild) what *kind of story* to reconstruct. The model does the actual narrative reconstruction from whatever it has access to. The focus string costs ~100 tokens to inject while preventing hundreds of thousands of tokens of accumulated ballast.

### Context as Narrative, Not Information

Three observations from the corpus analysis support this:

1. **41% of exchanges are "conversational"** (zero tool calls). These are short confirmations, clarifications, or explanations. They are high-value semantic context but zero-value mechanically — and they are the first thing generic compaction discards.

2. **Tool sequences are highly regular.** 79 recurring phase patterns explain the vast majority of work phases. The model doesn't need to remember *which* files it read — it needs to know it's in an "implement" phase (Read→Edit→Bash cycle) working on sources.py and forensics.py because the user asked to "add per-subagent forensics."

3. **Phase transitions are predictable.** The most common session rhythm is `shell ↔ conversational` (30% of all transitions) — the user gives instruction, the model executes, repeat. The narrative frame captures where in this rhythm the session currently sits.

### Why Aggressive Compaction Can Improve Performance

At 5% context utilization with aggressive clear-and-rebuild, each micro-session is effectively a **fresh model with perfect orientation**:

- No accumulated confusion from stale file reads
- No attention dilution across resolved reasoning
- No superseded diffs competing for attention
- Just a clean window with a precise narrative frame and the relevant files re-read fresh

The narrative frame costs ~100 tokens. The ballast it replaces costs hundreds of thousands. The model's effective intelligence budget goes from ~36% (attention diluted across stale context) to near 100% (clean context, precise orientation).

## Implementation

### Architecture Overview

```
UserPromptSubmit hook
  → record_user_text() — captures user's intent

PostToolUse hook (every tool call)
  → record_tool() — appends to sliding window
  → abstract to pattern alphabet (R/W/X/A/M)
  → match against discovered pattern catalog
  → update phase state on disk

PreCompact hook
  → build_narrative_frame() — constructs focus string from:
    - current phase pattern + archetype metadata
    - user's last prompt text
    - active file list (from tool inputs)
  → returns as additionalContext, shaping what compact retains
```

### Pattern Discovery (Offline)

The pattern catalog is generated by `analysis/pattern_discovery.py`, a standalone script that extracts behavioral patterns from the full Claude Code session corpus.

**Corpus**: All JSONL session files in `~/.claude/projects/` across all projects, including subagent transcripts. The current corpus spans 110 sessions, 6,640 exchanges, 1,628 subagents, and 16 projects over 30 days.

**Extraction pipeline**:

1. **Exchange extraction**: Parse JSONL files line-by-line. Group messages into "exchanges" — one user prompt plus all subsequent assistant responses and tool calls until the next substantive user prompt. Captures user text, assistant text, tool sequences, tool input summaries, and token usage per exchange.

2. **Subagent extraction**: Subagent JSONL files have no user prompts (their "user" messages are tool_result blocks). They are parsed into `SubagentRecord` objects that capture the initial Agent task prompt, all assistant text, and the full tool sequence. Subagent tool sequences feed into the n-gram analysis alongside exchange tool sequences.

3. **Phase splitting**: Sessions are split into work phases at natural boundaries — mode transitions between tool-heavy exchanges, gaps of 2+ consecutive conversational exchanges, or a cap of 10 exchanges per phase. Each phase captures the concatenated tool sequence, user text, and files touched.

**Analysis layers**:

- **Tool n-grams** (1-4): Frequency counts of tool sequence patterns across all exchanges and subagents. 19,687 Bash calls, 9,820 Read calls, etc.
- **Mode classification**: Each exchange is classified into a workflow mode (explore, implement, debug, shell, delegate, navigate, mixed, conversational) using tool-type proportions. Extends the existing `behavior.py:_infer_workflow_mode()`.
- **Verb-intent correlation**: Leading verbs from user prompts are correlated with workflow modes. "push" → shell (83%), "read" → explore (63%), "update" → implement (60%).
- **Phase archetype discovery**: Each work phase's tool sequence is abstracted to a 5-symbol alphabet and run-length encoded. Recurring patterns (appearing 3+ times) become the archetype catalog.

**Pattern alphabet**:

| Symbol | Tools | Meaning |
|--------|-------|---------|
| R | Read, Grep, Glob | Reading/searching |
| W | Edit, Write | Modifying files |
| X | Bash | Shell execution |
| A | Agent | Delegation |
| M | mcp__* | MCP tool calls |
| ? | Other | Unclassified |

**Run-length encoding**:

| Notation | Meaning |
|----------|---------|
| X | 1-3 consecutive occurrences |
| X+ | 4-8 consecutive occurrences |
| X++ | 9+ consecutive occurrences |

This produces patterns like `RWX` (read-edit-test — the atomic implementation cycle), `X++` (long shell chains — iterative debugging/testing), `R+` (multi-file exploration), `RWRWRWX` (systematic multi-file edit then test).

**Output**: `analysis/patterns.json` — a machine-readable catalog with 79 phase archetypes, each annotated with occurrence count, dominant mode, top intents, top verbs, and example concrete tool signatures.

### Runtime Phase Matcher (`src/prism/phase_matcher.py`)

Pure CPU, no LLM calls. Runs on every PostToolUse hook event.

**Sliding window**: Maintains the last 30 tool calls per session as both raw tool names and abstract symbols. State is persisted to `~/.claude/prism/phase_state/{session_id}.json` — survives across hook invocations within a session.

**Pattern matching**: On each tool call, the window suffix is run-length encoded and matched against the pattern catalog. Tries progressively shorter suffixes (from 20 symbols down to 2) to find the longest matching pattern. If the catalog file is absent, the matcher falls back to direct mode inference from symbol proportions.

**Active file tracking**: File paths from Read/Edit/Write tool inputs are accumulated into the phase state. The narrative frame includes basenames of the 5 most recent files.

**User text capture**: The UserPromptSubmit hook (new) captures the user's natural language prompt text and stores it in the phase state. This provides the "intent" component of the narrative frame without any LLM inference — it's the user's own words.

### Narrative Frame Builder

Called from the PreCompact hook. Assembles a compact focus string (~100 tokens) from three signals:

1. **Phase type**: The matched pattern key + its archetype metadata (dominant mode, top intents). Example: "Work phase: build_feature/test (RWX)"
2. **User intent**: First sentence of the user's last prompt. Example: "User request: Add per-subagent forensics breakdown to Prism"
3. **Active files**: Basenames of recently touched files. Example: "Files: sources.py, forensics.py"

These compose into:

```
[Prism] Compact focus: Work phase: implementing (RWX) | User request: Add per-subagent forensics breakdown to Prism | Files: sources.py, forensics.py | Tools used: 42
```

This is delivered via `additionalContext` in the PreCompact hook response, which Claude Code injects into the compaction process to shape what survives.

### Hook Integration

Six hook events are handled, five pre-existing and one new:

| Hook | Handler | What it does |
|------|---------|-------------|
| PostToolUse | `handle_post_tool_use` | Records tool event + feeds tool name and input summary to phase matcher |
| SessionStart | `handle_session_start` | Initializes session event stream |
| PreCompact | `handle_pre_compact` | Records compaction boundary + injects narrative focus frame via `additionalContext` |
| Stop | `handle_stop` | Computes efficiency metrics, writes summary + bridge file |
| SessionEnd | `handle_session_end` | Delegates to Stop handler |
| **UserPromptSubmit** | `handle_user_prompt` | **New.** Captures user prompt text for narrative frame. Silent (no output). |

The UserPromptSubmit hook is registered in `~/.claude/settings.json` pointing at the same `prism-hook` entry point. The dispatch table routes it to `handle_user_prompt`.

### Subagent Forensics (`src/prism/sources.py`, `src/prism/forensics.py`)

The forensics lens now provides per-subagent breakdown, not just aggregate counts.

**Data model changes** (`sources.py`):

- `SessionData` gains three fields: `subagents: list[SessionData]` (individual parsed subagent sessions), `agent_id: str`, `agent_type: str` ("compact" or "spawned")
- `_collect_subagents()` now stores each parsed subagent in the list AND classifies it by checking for "compact" in the filename (the `acompact-*` prefix indicates a context continuation, not a spawned agent)
- Backward compatible: `subagent_count` and `subagent_usage` aggregates are still computed from the list

**Forensics output** (`forensics.py`):

- New `_subagent_summary()` function produces per-agent breakdowns: agent_id, type (compact/spawned), tokens, cache hit rate, duration, tool call count, tool distribution, and read/edit ratio
- The `subagents` section in forensics output now includes `compact` count, `spawned` count, and an `agents` array sorted by token usage descending
- Drill-down via `prism_details(id, "sessions", "0.subagents.agents.0.tool_distribution")` navigates into individual agent tool breakdowns

This classification was the key diagnostic that revealed the "97.6% subagent cost" was actually "the main session's second half after compaction" — not rogue subagents.

## Operating the System

### Re-running pattern discovery

As the corpus grows, re-run to update the catalog:

```bash
cd /Users/rohanvinaik/tools/Prism
.venv/bin/python analysis/pattern_discovery.py --include-subagents
```

The runtime matcher picks up the updated `analysis/patterns.json` on next session start (catalog is cached in-process, refreshed per session).

Options:
- `--since N` — only analyze the last N days
- `--project FILTER` — filter to a project name substring
- `--output PATH` — custom output path (default: `analysis/patterns.json`)

### Checking the current phase state

From any Prism MCP tool or directly:

## Future Directions

### Proactive compaction triggering

The current system is reactive — it injects a narrative frame when compaction happens. The next step is proactive triggering: the phase matcher detects a phase transition (e.g., explore → implement) and triggers `/compact` before the context window fills, with the outgoing phase's narrative frame as focus. This implements the "5% context" strategy where compaction happens at natural work boundaries, not at the context limit.

### Narrative frame refinement via Mneme

The current verb-intent correlation uses keyword matching. Mneme's EPA (Evaluation, Potency, Activity) decomposition of session text provides a geometric signal that could replace or augment the keyword approach. High-Potency text maps to implementation phases; high-Activity text maps to exploration. This is the Winstonian "story type" layer — classifying the kind of narrative, not its content.

### Cross-session pattern learning

The pattern catalog is currently static (regenerated manually). A feedback loop where runtime pattern matches are scored against compaction outcomes (did the post-compact session perform better?) would allow the catalog to evolve. Patterns that produce good compact frames get reinforced; patterns that don't get deprecated.
